# Контракт данных лендинга (`site/data/`)

Лендинг (`site/index.html` + `site/js/app.js`) – статичная страница для GitHub Pages: без сборки и бэкенда, данные подгружаются `fetch` из `site/data/`. Пока реальных результатов нет, файлы генерирует `site/data/make_mock.py` (мок строго по этому контракту). Реальный конвейер должен записать **те же файлы с теми же именами и полями** – код лендинга менять не нужно.

```bash


python -m http.server 8765 -d site               # открыть http://localhost:8765
```

## Общие соглашения

- Кодировка UTF-8, JSON без NaN/Infinity: пропуск – `null`.
- `territory_id` – целое в GeoJSON и **строка-ключ** в `labels.json` (ключи объектов JSON всегда строки).
- Месяцы – строки `"YYYY-MM"`; все массивы «по месяцам» имеют длину `len(meta.months)` (24) и тот же порядок.
- Типы нумеруются `0..K-1`; `-1` – «нет данных в этом месяце / МО вне панели».
- Цвет типа задаётся один раз в `types.json` и используется везде (карта, легенда, Sankey, паспорта).
- Обязательные файлы: `meta.json`, `types.json`, `labels.json`, `transitions.json`, `mo.geojson`. Необязательные: `regions.geojson`, `methods.json`, `cases.json` (если файла нет, соответствующий слой/раздел скрывается).

## Геометрия

### `mo.geojson` – границы МО
`FeatureCollection`, одна `Feature` на МО (`Polygon` или `MultiPolygon`), координаты WGS84 (lon, lat).

| поле `properties` | тип | смысл |
|---|---|---|
| `territory_id` | int | ключ МО (тот же, что в `consumption.parquet`) |
| `name` | str | название МО |
| `region` | str | субъект РФ |
| `type` | str | тип МО по справочнику (городской округ, муниципальный район, …) |
| `in_panel` | bool | `true` – МО в обучающей панели (24 из 24 мес.); `false` – классифицировано по ближайшему центру, на карте помечается |

Требования к геометрии:
- **Разрез по 180°.** Полигоны, пересекающие антимеридиан (Чукотка), разрезаются на части `[…, 180]` и `[-180, …]` (`antimeridian.fix_geojson` или mapshaper). Карта рисуется в проекции Альберса с осевым меридианом 100° в. д., поэтому части стыкуются без «полосы через весь мир».
- **Порядок обхода колец – любой.** `app.js` при загрузке перематывает кольца под требование d3-geo (внешнее – по часовой стрелке); без этого Plotly заливает «весь глобус минус МО».
- Размер: цель ≤ 4–5 МБ (упрощение 1000 м по `configs/geo.yaml` даёт ≈ 3,9 МБ на 2190 МО). GitHub Pages отдаёт gzip.

### `regions.geojson` – контуры регионов (необязательный)
`FeatureCollection`, `properties.region` (str). Рисуется линиями поверх МО (линии не перехватывают клики по МО). Удобно получить `dissolve` уже упрощённых МО по `region`.

## `meta.json`

```jsonc
{"months": ["2023-01", "…", "2024-12"], "k": 6, "method": "kefrin",
 "generated": "2026-10-08T12:00:00", "n_panel": 2016, "n_all": 2190,
 "attribution": "Данные: Лаборатория СберИндекс, CC BY-SA 4.0", "mock": false}
```

| поле | смысл |
|---|---|
| `months` | ось времени всех рядов |
| `k` | число типов K |
| `method` | итоговый метод; его строка выделяется в таблице методов (ключи: `kefrin`, `temporal_leiden`, `leiden`, `spectral`, `kmeans`, `ward`) |
| `generated` | ISO-дата сборки данных (показывается в подвале) |
| `n_panel`, `n_all` | МО в панели / всего (шапка) |
| `attribution` | строка атрибуции (подвал) |
| `mock` | *необязательно*; `true` – показать плашку «демонстрационные данные». В реальных данных – `false` или не указывать |

## `types.json` – паспорта типов
Массив из K объектов, отсортирован по `id`:

```jsonc
{"id": 0, "name": "Крупные города и столичные центры", "short": "Города", "color": "#0072B2",
 "description": "абзац экономиста",
 "n": 260, "share": 0.119,
 "profile": {"Продовольствие": -1.3, "Здоровье": 0.6, "Маркетплейсы": 0.7, "Общественное питание": 1.6,
             "Транспорт": 0.9, "Прочее": 0.8, "Уровень трат": 1.4},
 "medians": {"Продовольствие, %": 33.0, "Здоровье, %": 5.5, "Маркетплейсы, %": 17.9, "Общественное питание, %": 4.9,
             "Транспорт, %": 8.1, "Прочее, %": 30.7, "Траты на жителя, ₽": 36900, "к медиане страны, %": 138},
 "typical": [{"territory_id": 123, "name": "…", "region": "…"}],
 "border":  [{"territory_id": 456, "name": "…", "region": "…"}],
 "external": {"Зарплата, ₽": 78000, "Население, тыс.": 410, "Доступность рынков, индекс": 0.82}}
```

| поле | смысл |
|---|---|
| `name` / `short` | полное имя (паспорт, подсказки) / короткое (легенда, Sankey, матрица – до ~12 символов) |
| `color` | hex; рекомендованная палитра (Okabe–Ito без жёлтого, порядок проверен на различимость при дальтонизме): `#0072B2 #E69F00 #009E73 #D55E00 #56B4E9 #CC79A7`, далее `#8C6D31 #332288 #999933 #882255`. Если поля нет – берётся эта палитра по `id` |
| `n`, `share` | число и доля МО типа (по подтверждённым типам последнего месяца) |
| `profile` | 7 признаков кластеризации, среднее типа в σ от средней по стране (порядок ключей = порядок столбцов на графике) |
| `medians` | медианы в читаемых единицах; ключ – подпись с единицей. Формат по ключу: `₽` и «медиане» → целое, `%` → один знак |
| `typical`, `border` | по 3 МО: ближайшие к центру / пограничные; кликабельны (открывают паспорт МО на карте) |
| `external` | внешние показатели (Росстат, справочник), **не** участвовавшие в кластеризации; произвольные ключи с единицей в подписи |

## `labels.json` – метки и ряды по МО
Объект `{ "<territory_id>": {...} }` для каждого МО из `mo.geojson`:

```jsonc
{"1673": {"name": "Орск", "region": "Оренбургская область",
          "type":       [1, 1, 1, …],      // сырой тип по месяцам, int, -1 = нет МО в месяце
          "confirmed":  [1, 1, 1, …],      // подтверждённый тип (смена ≥ 3 мес. подряд и бутстрэп ≥ 0,7)
          "confidence": [0.93, 0.88, …],   // бутстрэп-вероятность типа, 0..1 (0 или null – нет данных)
          "level":      [21964, 22950, …], // траты на жителя, ₽ (null – нет данных)
          "shares": {"Продовольствие": [0.42, …], "Здоровье": […], "Маркетплейсы": […],
                     "Общественное питание": […], "Транспорт": […]}}}   // доли 0..1; «Прочее» = 1 − сумма считается на лету
```

- Карта красит МО по `confirmed[t]` (режим «подтверждённые») или `type[t]` (режим «сырые»).
- Слой неопределённости: непрозрачность полигона растёт с `confidence[t]`; ниже 0,7 МО почти прозрачно.
- Клик по потоку Sankey выделяет МО, у которых `confirmed[i_from] == from` и `confirmed[i_to] == to`, где `i_from`, `i_to` – индексы `transitions.from_month`/`to_month` в `meta.months`.
- Объём: ~1,5 КБ на МО → ≈ 3,3 МБ на 2190 МО (gzip ≈ 0,8 МБ). Округляйте: доли – 4 знака, уверенность – 3, уровень – целое.

## `transitions.json` – динамика

```jsonc
{"from_month": "2023-12", "to_month": "2024-12",
 "matrix": [[0.78, 0.0, …], …],          // K×K, доли строки (строка – откуда), по подтверждённым типам
 "counts": [[203, 0, …], …],             // K×K, число МО
 "shorrocks": {"raw": 0.31, "confirmed": 0.08},
 "flows": [{"from": 0, "to": 2, "n": 45, "period": "2023→2024"}, …],
 "events": [{"month": "2024-03", "event": "split", "from": [1], "to": [1, 4], "jaccard": 0.6}, …],
 "sizes": {"2023-01": [n_0, …, n_{K-1}], …},   // число МО по подтверждённым типам в каждом месяце
 "stable_share": 0.76}                          // доля МО панели без смен подтверждённого типа за 24 мес.
```

- `from_month`, `to_month` – *необязательны*, по умолчанию `"2023-12"` и последний месяц. Они задают и подписи Sankey, и правило выделения МО на карте.
- `flows` должны включать и диагональ (`from == to`) – «оставшиеся» потоки рисуются бледнее. Если `flows` пуст, потоки строятся из `counts`.
- `event` ∈ `split | merge | continue | grow | shrink | birth | death` (подписи по-русски в `app.js`, неизвестные показываются как есть).

## `methods.json` – сравнение методов (необязательный)

```jsonc
{"k_fixed": 6,
 "rows": [{"method": "kefrin", "SW": 0.21, "CH": 650, "S_Dbw": 0.9, "AVI": 0.6, "AVU": 0.4, "MQ": 0.55,
           "ANUI": 0.5, "borda": 24, "threshold_rank": 1, "win_rate": 0.7}, …],
 "pareto": [{"method": "kefrin", "SW": 0.21, "MQ": 0.55}, …],
 "layers": [{"layer": "fused", "method": "kefrin", "SW": 0.21, "MQ": 0.55, "ari_vs_fused": 1.0}, …],
 "directions": {"SW": "max", "CH": "max", "S_Dbw": "min", "AVI": "max", "AVU": "min", "MQ": "max",
                "ANUI": "max", "borda": "max", "threshold_rank": "min", "win_rate": "max"},
 "notes": "AVU вырожден при K≤3; MQ = модулярность Q"}
```

- Все числовые поля `rows` становятся столбцами таблицы ICVI (известные – в фиксированном порядке, прочие – в конце). Лучшее значение в столбце подсвечивается по `directions` (*необязательно*; по умолчанию – как в `src/pulsar/icvi.py::DIRECTION`). `win_rate` показывается в процентах.
- `pareto` – методы на фронте Парето «SW vs MQ» (по ним рисуется линия фронта; остальные точки – полые).
- `layer` ∈ `fused | behavior | comovement | geo | behavior+comovement | behavior+geo | comovement+geo` (подписи по-русски), строка `fused` выделяется.

## `cases.json` – кейсы (необязательный)

```jsonc
[{"title": "Орск: паводок апреля 2024", "territory_id": 1673,
  "months_highlight": ["2024-04", "2024-05"],
  "text": "абзац 1\n\nабзац 2", "chart": "level"}]
```

- `chart`: `level` – траты на жителя (точки окрашены подтверждённым типом), `shares` – доли пяти категорий (лог. шкала).
- `months_highlight` – закрашиваемый интервал (от первого до последнего месяца списка); первый месяц выставляется на карте по кнопке «Показать на карте».
- `text` – абзацы через пустую строку; HTML не интерпретируется.

## Проверка после подмены данных

1. `python -m http.server 8765 -d site`, открыть `http://localhost:8765`, консоль без ошибок; строка `[pulsar] карта построена за … мс (N МО)`.
2. Шапка: число МО и доля стабильных совпадают с `meta.json` / `transitions.json`.
3. Чукотка не даёт полосы через карту; в легенде нет лишнего «нет данных» у МО панели.
4. `window.__pulsarLastRenderMs` после движения ползунка < 300 мс (на моке 2190 × 100 вершин – ≈ 5 мс).
